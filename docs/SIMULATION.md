# Simulation on a laptop (no robot, no Gazebo)

`sim_robot` replaces the hardware: it moves a simulated base from velocity commands and ray-casts
a fake lidar against a floor-plan image. Everything above it is the real stack with the real
`nav2_params.yaml`: slam_toolbox, AMCL, Nav2, collision monitor, patrol, dashboard.

Needs ROS 2 Humble with Nav2 and slam_toolbox on the laptop. Nothing else to install.

```bash
source /opt/ros/humble/setup.bash && colcon build --symlink-install     # once, in the repo root
source scripts/sim_env.sh                                               # every terminal

ros2 launch ame505_bringup navigation_2d.launch.py map:=sim_hall use_rviz:=true use_teleop:=false
ros2 run ame505_bringup patrol --map sim_hall --dwell 2                 # second terminal
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r cmd_vel:=/controller/cmd_vel   # drive by hand
ros2 launch ame505_bringup mapping_2d.launch.py map:=my_sim_map use_rviz:=true use_teleop:=false  # make a map
```

`scripts/sim_env.sh` sets `AME505_SIM=1` (so `robot.launch.py` starts `sim_robot` instead of the
Hiwonder drivers), keeps data in `~/ame505_sim_data`, copies the sample map and patrol route there,
and sets `ROS_LOCALHOST_ONLY=1`. **Keep that last one:** on the lab Wi-Fi a simulation would
otherwise publish `/cmd_vel` to the real robot.

## The world

`src/ame505_bringup/sim/`, generated by `scripts/make_sim_world.py`: a 20 m x 9 m hallway with six
rooms, 5 cm cells. The robot starts at the map origin, in the hallway 2 m from the west wall.

| File | Used by |
|---|---|
| `sim_hall.pgm/.yaml` | AMCL and Nav2: the saved map (walls and fixed furniture) |
| `sim_hall_world.pgm/.yaml` | the simulated lidar: the map plus two boxes that are not on the map |
| `sim_hall_checkpoints.yaml` | sample 8-checkpoint patrol route |

To use a real map: copy the robot's `maps_2d/<name>.pgm/.yaml` into `~/ame505_sim_data/maps_2d/`
and launch with `map:=<name> sim_world:=<path to that .yaml>`.

## What is and is not simulated

| Simulated | How |
|---|---|
| Lidar `/scan` | 12 Hz, 360 beams in `lidar_frame`, only the robot-front 180° valid, 1 cm noise, 0.2–12 m |
| Odometry `/odom`, TF `odom -> base_footprint` | believes the commanded speed; the true robot slips (3 % forward, 12 % sideways, 5 % turning), so odometry drifts and AMCL has to correct it |
| Walls | the robot stops and logs `BUMP` when its 0.18 m circle touches one |
| People (optional) | add `sim_people:=default` to the launch: two walkers and two people who stand in doorways part of the time (`sim/sim_hall_people.yaml`). The lidar sees them, the robot cannot drive through them, and `CONTACT` is logged if it drives into one. RViz: add a MarkerArray display on `/sim/people` |
| `/imu`, battery | so the dashboard has data |
| True pose | `/sim/ground_truth`, to measure localization error |

Not simulated: the depth camera (so no dataset capture and no hazard detection), wheel and motor
dynamics, the motor board keeping its last speed, and the Jetson Nano's CPU load. Timing problems
seen on the robot (late TF, missed heartbeats) will not show up here.
